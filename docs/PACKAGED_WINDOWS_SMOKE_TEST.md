# Packaged Windows Smoke Test

Use this when validating the installed Windows app, not the Vite web shell. The harness creates a repeatable local filesystem corpus and prints the exact searches to run in StackDrop.

## Build and Install

From the repo root:

```powershell
npm ci
npm run typecheck
npm run test
npm run build
npm run tauri -- build
```

The Windows bundle is usually under:

```text
src-tauri\target\release\bundle\
```

Common outputs include:

```text
src-tauri\target\release\bundle\nsis\*.exe
src-tauri\target\release\bundle\msi\*.msi
```

Install the generated app, then launch StackDrop from the Start menu.

## Harness Commands

Default corpus path:

```text
%USERPROFILE%\Desktop\StackDropManualTest
```

Run commands from the repo root:

```powershell
npm run smoke:windows:setup
npm run smoke:windows:mutate
npm run smoke:windows:clean
```

All harness actions are available directly:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action setup
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action mutate
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action offline
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action restore
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action permission-denied
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action restore-permissions
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action clean
```

Use `-Force` with `setup` to replace an existing generated corpus:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action setup -Force
```

The harness writes:

```text
%USERPROFILE%\Desktop\StackDropManualTest\stackdrop-smoke-manifest.json
```

The manifest contains generated paths, unique tokens, expected queries, mutation steps, and cleanup commands.

## What the Harness Creates

Setup creates:

- `normal.txt` with a unique body token
- `empty.txt`
- `file-name-hyphen.txt`
- `file_name_underscore.txt`
- `Nested\nested-note.txt`
- `simple.docx`
- `selectable-text.pdf`
- `corrupt.pdf`
- `unsupported-placeholder.xlsx`
- `large-over-50mb.txt`
- watcher baseline files under `Watcher\`

The DOCX and selectable PDF are generated by the PowerShell script using .NET APIs. No Office, Python, or PDF utility dependency is required.

## Manual App Steps

After `setup`:

1. Launch the installed StackDrop app.
2. Click **Add folder** if the generated folder is not already indexed.
3. Select:

   ```text
   %USERPROFILE%\Desktop\StackDropManualTest
   ```

4. Click **Index library**.
5. While indexing is active, confirm the index controls show live progress such as the current folder or file, discovered/indexed/failed counts, and elapsed time instead of only `Scanning...`.
6. Open **Index Diagnostics** and confirm totals, failures, folder health, and parse/read failure explanations are understandable.
7. Run the setup queries printed by the harness.

After `mutate`:

1. Keep StackDrop open with **Auto-index while open** enabled.
2. Wait until the Index controls line shows **Watching indexed folders** before running the mutation command. Startup watcher registration may take time on larger existing roots.
3. If automation inserted the smoke root directly into the packaged SQLite DB instead of using **Add folder**, restart the installed app before watcher testing so startup loads the root from the DB and registers it with the watcher.
4. Only click **Index library** after the watcher check if you need a manual cleanup/resync pass.
5. Run the mutation queries printed by the harness.
6. Confirm old edit/rename/delete searches disappear and new create/edit/rename/move searches appear.

After `offline`:

1. The harness renames the indexed root to `StackDropManualTest.offline`.
2. In StackDrop, click **Index library**.
3. Confirm existing rows are not wiped and **Index Diagnostics** shows a root issue for the original root path.
4. If the row has a timeout plus unprocessed files, confirm it is described as **Partial scan**, shows the unprocessed count, and offers **Re-scan this folder** without claiming exact resume.

After `restore`:

1. The harness renames the root back.
2. In StackDrop, click **Index library**.
3. Confirm the root issue clears after a successful scan.

After `permission-denied`:

1. The harness creates `PermissionDenied\permission-denied-token.txt`.
2. It applies an explicit read/list deny ACE for the current Windows user on the `PermissionDenied` folder.
3. In StackDrop, click **Index library**.
4. Confirm diagnostics show either a root-level scan issue or a read failure, depending how Windows traversal reports the denied folder.

## Query Expectations

The script prints these after each phase and records them in the manifest.

Setup:

| Query | Expected result |
|---|---|
| `STACKDROP_SMOKE_NORMAL_TXT_20260627` | `normal.txt` appears as parsed text. |
| `empty.txt` | `empty.txt` appears by filename/path. |
| `file-name-hyphen` | `file-name-hyphen.txt` appears. |
| `file_name_underscore` | `file_name_underscore.txt` appears. |
| `STACKDROP_SMOKE_NESTED_TXT_20260627` | `Nested/nested-note.txt` appears. |
| `STACKDROP_SMOKE_DOCX_20260627` | `simple.docx` appears if bundled DOCX parsing works. |
| `STACKDROP_SMOKE_PDF_TEXT_20260627` | `selectable-text.pdf` appears if bundled PDF parsing works. |
| `corrupt.pdf` | `corrupt.pdf` appears by filename and shows parse failure. |
| `STACKDROP_SMOKE_UNSUPPORTED_XLSX_20260627` | No result; `.xlsx` is unsupported. |
| `large-over-50mb` | `large-over-50mb.txt` appears by filename and shows read failure. |

Mutate:

| Query | Expected result |
|---|---|
| `STACKDROP_SMOKE_WATCH_CREATE_20260627` | `Watcher/watcher-created.txt` appears. |
| `STACKDROP_SMOKE_WATCH_EDIT_BEFORE_20260627` | No result after re-index. |
| `STACKDROP_SMOKE_WATCH_EDIT_AFTER_20260627` | `Watcher/watcher-edit.txt` appears. |
| `watcher-rename-before` | No result after re-index. |
| `watcher-rename-after` | `Watcher/watcher-rename-after.txt` appears. |
| `watcher-moved` | `Moved/watcher-moved.txt` appears. |
| `STACKDROP_SMOKE_WATCH_DELETE_20260627` | No result after re-index. |

Offline:

| Check | Expected result |
|---|---|
| Index Diagnostics | Root issue appears for `%USERPROFILE%\Desktop\StackDropManualTest`; existing indexed rows are not wiped. |

Permission denied:

| Query | Expected result |
|---|---|
| `STACKDROP_SMOKE_PERMISSION_DENIED_20260627` | Usually no result; diagnostics show root issue or read failure. |

## Restore Permissions Safely

If you ran `permission-denied`, restore permissions before cleanup:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stackdrop-packaged-smoke.ps1 -Action restore-permissions
```

The script removes explicit deny ACEs for the current Windows identity from both:

```text
%USERPROFILE%\Desktop\StackDropManualTest
%USERPROFILE%\Desktop\StackDropManualTest.offline
```

Then clean:

```powershell
npm run smoke:windows:clean
```

## Remaining Manual Risks

This harness automates corpus creation and real filesystem mutation. It still cannot fully automate:

- Launching and observing the installed desktop app if UI automation is unavailable.
- OS-specific watcher timing; wait for **Watching indexed folders** before mutations, then allow one debounce/poll window before declaring failure.
- OneDrive/Dropbox online-only placeholder behavior; add a cloud-backed folder manually if needed.
- Visual confirmation that diagnostics and result states are understandable.
- Antivirus, enterprise policy, or Windows ACL differences on the test machine.
